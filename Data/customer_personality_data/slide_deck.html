04 Foundation

Cleaning Applied

Five changes, applied to both tracks before any analysis — none of them touch Response or Income directly.

  • 01 Drop ID — identifier, not a feature
  • 02 Drop Z_CostContact / Z_Revenue — constant columns
  • 03 Parse Dt_Customer → derive Customer_Tenure_Days A raw date string has no numeric meaning on its own. Re-expressed as days since enrollment, relative to the dataset's latest signup (2014-06-29) — a usable behavioral signal instead.
  • 04 Derive Age from Year_Birth — 3 outlier rows (121/115/114 yo) dropped Birth years 1893/1899/1900 are almost certainly data-entry errors, not real ages. Only 3 of 2,240 rows — too few to impute credibly, so dropped outright.
  • 05 Collapse Marital_Status joke categories (Absurd/YOLO/Alone → Single) Absurd/YOLO (2 rows each) read as placeholder joke entries; Alone (3 rows) means the same thing as Single. All three too small to analyze as their own category.
Result Final cleaned shape: 2,237 rows × 28 cols — down from 2,240 × 29. Of those 28, Dt_Customer/Year_Birth stay in raw form but aren't used directly — each track's candidate list uses the derived Customer_Tenure_Days/Age instead. Minus each track's own target (Response or Income) → 25 candidates per track.

07 Classification

Relevance Score — How It's Computed

Two methods, split by feature type — both scored against Response (0/1), both judged against the same 0.10 threshold so the results sit on one ranked chart.

Point-biserial correlation

For the 16 numeric candidates. Codes Response as 0/1 and correlates it directly — the formula is Pearson r, not just "like" it. Why: it's the standard linear-association measure for numeric-vs-binary, and its sign shows which class a feature leans toward.

r_pb  =  ((M_1 − M_0) / s_n)  ·  √(n_1·n_0 / n²)

M₁, M₀ = feature mean where Response = 1 / 0 · s_n = feature's std · n₁, n₀, n = group / total sizes

Cramér's V

For the 2 nominal candidates (Education, Marital_Status) — categories have no numeric order, so Pearson can't apply. Why: a chi-square test of independence on the contingency table, rescaled to a bounded 0–1 score.

V  =  √( χ² / (n · min(k−1, r−1)) )

χ² = chi-square statistic on the contingency table · n = rows · k, r = table columns / rows

Threshold |score| ≥ 0.10 to be considered relevant.
08 Classification

Not Actually Leakage — Here's Why

Before the chart on the next slide shows some bars colored differently — what that color means, and why it isn't the "L word" it might look like.

What leakage actually means

A feature that would not actually be available at prediction time — information from the future, or a feature mathematically/causally derived from the target itself (e.g. a target-encoded column, or using tomorrow's known outcome to predict today).

Why AcceptedCmp1–5 don't qualify

Each flags whether the customer accepted one of the five earlier campaigns — Response's campaign always comes after them. In the deployment scenario this model is for (deciding whether to send an existing customer the newest campaign), that history is always available before the prediction is needed. Legitimate, temporally-valid historical-behavior signal.

Strong historical predictor, not leakage A customer who already said yes once is a genuinely more receptive, campaign-responsive person — a real behavioral trait, not a target-derived artifact: Response rate given any prior campaign acceptance is 40.7% (n=462) vs. 8.2% given none (n=1,775), a 5× gap. The one caveat worth keeping: a brand-new prospect with no campaign history wouldn't have this feature populated — a feature-availability / cold-start issue, not leakage.

14 Classification

Cross-Check — Mutual Information

What it is

An information-theoretic measure: how much knowing a feature's value reduces uncertainty about Response. Unlike Pearson/point-biserial, it isn't limited to linear relationships — it catches any statistical dependency, monotonic or not.

mutual_info_classif · range 0 → ∞, no fixed upper bound · 0 = independent

Why run a third method

Point-biserial only sees linear signal; RF importance depends on how trees happen to split — greedy, order-sensitive, distorted by multicollinearity. MI asks a cleaner question: is there any dependency at all, regardless of shape? Agreement across all three is a stronger claim than any one method alone.

16 Foundation

Feature Selection — The Cutting Rule

Three methods, three different scales — how bivariate relevance, RF importance, and MI collapse into one keep/cut decision. Same rule, applied independently on both tracks.

Not an average

The three scores live on incompatible scales: bivariate is signed, −1 to +1; RF importance is unsigned, 0 to 1, and sums to exactly 1 across all candidates; MI is unsigned, 0 to ∞ with no fixed ceiling. Averaging them would let whichever method has the largest numeric range dominate a blended score, for no principled reason.

The vote — one pass/fail per method

  • Bivariate passes if |score| ≥ 0.10
  • RF passes if the feature lands in RF's top-N
  • MI passes if the feature lands in MI's top-N

Tiered by vote count

  • 3/3 full consensus → chosen, no caveat (unless separately flagged for availability/multicollinearity)
  • 2/3 lower-confidence signal → generally cut, kept only with a specific named reason
  • ≤1/3 → cut
Why this beats trusting one method A signal that survives three different statistical assumptions at once is unlikely to be a fluke of any one method, or of this dataset's modest size (~2,200 rows per track).

21 Regression

Relevance Score — How It's Computed

Same split-by-feature-type logic as the classification track — but note: the two formulas below are not the same math, just parallel roles.

Pearson |r|

For the 23 numeric candidates vs. Income. Why: both sides are continuous, so the direct covariance-based linear-association measure applies — no special case needed.

r  =  Σ(x_i−x̄)(y_i−ȳ) / √( Σ(x_i−x̄)² · Σ(y_i−ȳ)² )

x̄, ȳ = feature / Income means · x_i, y_i = per-row values · reported as |r|

Correlation ratio η

Education / Marital_Status vs. Income. Why: nominal categories again rule out Pearson — this is an ANOVA-style ratio of between-group to total variance, unsigned since group order carries no meaning.

η  =  √( Σ_g n_g(ȳ_g−ȳ)² / Σ_i(y_i−ȳ)² )

g = a category group · n_g, ȳ_g = that group's size / mean Income · ȳ = overall mean

Not the same formula Pearson r and correlation ratio η play parallel roles (categorical analogue) but compute different things — η is a variance-explained ratio (0 to 1, unsigned), while r is a signed linear-slope measure (−1 to +1). Same threshold, different math.
22 Regression

Not Actually Leakage — This Track's Flavor

Same definition as the classification track (see earlier slide) — a feature that wouldn't actually be available at prediction time, or one mathematically/causally derived from the target. Neither flagged group here meets it either, for a different reason than the classify track.

Classify's flavor: cold-start, not leakage

AcceptedCmp1–5 are past behavior predicting future behavior — always available before prediction time for an existing customer. Not leakage; see the classify-track slide.

Regression's flavor: multicollinearity, not leakage

The Mnt* spend columns are a separately-observed variable about the same customer, co-occurring with Income — not computed from it, not causally downstream of it in a way the model exploits unfairly. Both plausibly reflect the same underlying economic capacity, which makes this a correlated / non-independent signal concern, already covered on the Multicollinearity slides.

No future info, not derived from Income Higher income gives more disposable spend — but spend is a separately-measured behavioral variable, not a mathematical function of Income, and it isn't drawn from any future period relative to Income. That rules out both canonical failure modes of leakage. Included as candidates, and the entanglement with Income is handled as multicollinearity, not flagged as leakage.
